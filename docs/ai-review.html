Codex response

What helps: The code checks HTTP status and validates the response fields before using them. The repository identity check is especially useful: a structurally valid response for the wrong repository is still rejected. A maintainer can see which fields the component expects, and HTTP errors have a different explanation from unexpected data.

One improvement: Move the compound response-shape condition into a named function, such as isRepositoryData(data, repository). Pass the expected repository explicitly and keep the existing checks. The function can return a boolean, leaving the current error message and throw in loadActivity().

Benefit and tradeoff: A named validation function would make the request handler easier to scan and give field validation a focused place to change when the API requirements change. The tradeoff is another function to navigate to. Keeping it in the same file would keep that cost small for this component.

Verification: Check a valid response, the wrong repository, an invalid date, a blank or overlong branch, a null language, and an unsupported language type. Repeat the component's HTTP-error, malformed-JSON, failure-and-retry, and success checks to confirm that extracting the condition preserves its behavior.
